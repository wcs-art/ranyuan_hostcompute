# EV1 睡眠监测上位机

燃元科技 EV1 睡眠监测设备的上位机软件。采集 EEG 4 通道 + fNIRS 10 通道（760/850 nm 双波长）数据，
实时显示、记录并导出为 EDF / SNIRF / XDF，同时通过 LSL 对外广播。

## 运行环境

- Python 3.10+

```bash
pip install -r requirements.txt
```

## 启动

最简单的方式：双击 `run.bat`。默认按 `config/run.json` 启动（当前为有线文本串口 COM3 @921600），
窗口打开即自动采集。

也可以在界面底部「采集、保存与串口」一栏里现场切换：

1. 选类型（文本串口 / 二进制串口 / UDP / TCP / 模拟数据）
2. 选端口（点「刷新端口」重新扫描 COM 口，也可手输）与波特率
3. 点「▶ 连接并采集」；再点一次即断开

换线、换口不必重启程序，也不必改配置文件。

命令行方式（参数优先于配置文件）：

```bash
python main.py --source=real  --proto=serial --com=COM3 --baud=921600
python main.py --source=text  --com=COM3 --baud=921600
python main.py --source=text  --replay=capture/text_field.bin
python main.py --source=dry   --replay=capture/demo.bin
python main.py --source=sim
```

> 同一个 COM 口不要同时被 VOFA、串口助手等工具打开。实测见过两种表现：
> ① `PermissionError(拒绝访问)`，端口直接打不开（2026-11-17 17:12 现场日志）；
> ② 能打开，但字节被两个程序分流，得到一串跳变脏值（实测 `-7218 → +6918`，而干净抓包正值个数为 0）。
> 两种都会让人误判成硬件问题。

### 看波形：14 图并排 / 单通道放大

- **双击任意子图** → 切到单通道大图（占满整个绘图区）；再双击大图、按 `Esc`、点大图右上角「← 返回 14 图」、
  或工具栏「⤢ 返回 14 图」都能回去。工具栏「⤢ 单通道放大」放大的是最近点过的那一张。
- 放大/还原是**切页**，不是搬动网格：14 图的格子位置与高度一点不变（实测单张可绘区 25.1px → 大图 623.1px → 还原 25.1px）。
- 大图的量程**只按这一路**算。14 图模式取所有通道里最大的那一路定档，小信号会被它压平。
- 纵轴默认「自动（按实测峰值）」：直接贴合峰值（余量 5%），曲线几乎顶到上下边框，
  这样才看得出浮动；单点毛刺按 0.5/99.5 分位剔除，不会把量程撑到上万把整屏压平。
- 需要绝对读数时切「EEG±100/±200/±500」固定档；滚轮/拖拽缩放后自动跟随会停住，点「跟随最新」恢复（放大/还原时会自动恢复跟随）。
- **鼠标只改时间轴**：纵轴不接受滚轮/拖拽（`setMouseEnabled(x=True, y=False)`）。
- **缩放不改变纵轴量程**：量程的基准恒取「最近一窗」（时间窗长度那段），跟你缩到哪一段时间无关。
  横向放大 50 倍时上下限之差一点不变（实测 10s→0.2s 恒为 3635），只有中心跟着那段的直流电平平移。
  旧实现每帧拿可见段重算，5 s 窗口 ±1729、0.2 s 窗口 ±942 —— 同一条曲线两种缩放两组读数，
  现场会判成"测量值在变"。缩出去看更早、幅度更大的历史时量程会自动抬高（只抬不压，避免削顶）。
- **曲线不会因为一路没数据而全没**：EEG 与 fNIRS 各自取各自的缓冲段。fNIRS 缓冲只留 3000 点
  （500 Hz 下 6 s），缩到更早的时段时只有 fNIRS 那 10 张图写「超出缓冲（仅存最近 6 s）」，
  EEG 照画（实测缩到 15~25 s，CH1 仍有 5000 点）。
- **放到最大有下限**：时间轴最窄 0.2 s（约 67 个采样点）。再窄就只剩一两个点，等于什么都看不见。
- **14 图的纵轴读数**写在每张图左上角两行（上=当前上限、下=当前下限，7pt 六位原值）。
  坐标轴本身不画数字：14 图并排时轴只有三十几像素宽，六位数字会被整段裁掉；要看完整刻度请双击放大。
  没有曲线时（停发/超出缓冲）读数会一起收起，空图上不会留着上一帧的数字。
- **时间轴**：「时间轴: 累计」（默认）横轴一路累加（0~10 → 20~30 → …），刻度就是"已经采到第几秒"；
  点一下切成「时间轴: 固定窗口」，横轴恒为 0~时间窗，只有波形滚动。两种模式下 14 张图都是同一把尺。
- **刻度上的数字就是收到的数字**：纵轴关掉了 pyqtgraph 的 SI 前缀缩写（默认会把 `-120300` 画成 `-120`，
  并把 `×1000` 藏进轴标签；我们给轴设了单位文字，这个乘数还会被静默丢掉，看上去像数据被改小了 1000 倍）。

## 有线的两种数据格式（不要混用）

| 格式 | 启动参数 | 内容 |
|---|---|---|
| AA55 二进制帧 | `--source=real --proto=serial` | 合同 F2 帧：帧头、包序号、CRC16、双时间戳、事件标记 |
| ASCII 文本行 | `--source=text` | 实测固件输出：每行一个十进制值 + `\r\n`，约 500 行/秒 |

文本格式不带帧头、序号、CRC、时间戳与事件，因此界面会标注「文本原始值 · 未换算 · 无 CRC/丢包校验」：
丢包统计与 CRC 校验不适用，数值为原始值（单位待定），指标面板不参与计算。
该格式**无法满足合同 F2 的验收判据**，两者不是同一条链路的两种写法。

数据源与协议（`v1` 104 字节 / `v1r5` 152 字节 / `compat90` 90 字节）在 `config/run.json` 中切换。

## 状态

- 有线串口文本行链路：已在真实设备上跑通 **[E3]**（COM3 @921600，固件实际输出约 500 行/秒，
  界面实测 475 Hz、波形正常刷新）。
- AA55 二进制帧链路（合同 F2 全字段）：未在真实设备上验证 **[E0]**。
- UDP / TCP 网络链路：未在真实模组上验证 **[E0]**。
- 文本格式缺帧头/序号/CRC/双时间戳/事件/设备号，合同 F2 的五项验收判据无法据此判定。
- 其余单元测试均为离线自测 **[E1]**，不构成链路验收证据。
